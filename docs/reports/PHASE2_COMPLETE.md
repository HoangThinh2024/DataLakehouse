## 1. Executive Summary
Phase 2 successfully implemented a high-performance, real-time Change Data Capture (CDC) pipeline. The architecture was pivoted from a heavy Kafka Connect (JVM) model to a "Redpanda-native" model using Redpanda Connect (Go), resulting in significant resource savings and improved system stability.

## 2. Key Deliverables

### A. Infrastructure Evolution
- **Redpanda Core:** Deployed Redpanda (v23.2.19) as the central event broker.
- **Tiered Storage:** Enabled automated archival from Redpanda topics directly to RustFS (S3) Bronze bucket. This ensures 100% of raw events are captured in the Lake without additional sink connectors.
- **Resource Limits:** Implemented strict memory and CPU limits across 20+ containers, preventing OOM (Out of Memory) issues and ensuring smooth operation on constrained hosts.

### B. Real-time CDC Pipeline
- **Engine:** Redpanda Connect (formerly Benthos) replaced Kafka Connect.

- **Dual-Path Ingestion:**

    2. **Storage Layer:** Parallel delivery to Redpanda topics for long-term S3 archival.
